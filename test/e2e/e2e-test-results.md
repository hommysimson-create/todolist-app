## 발견 및 수정된 버그

### BUG-01 ✅ 수정완료: 로그인 실패 시 오류 메시지 미표시
- **관련 시나리오**: SCN-14, SCN-15
- **근본 원인**: `frontend/src/api/client.ts`의 401 응답 인터셉터가 인증 여부와 관계없이 무조건 `window.location.href = '/login'`을 실행함. 로그인 요청 실패(미인증 상태의 401) 시에도 페이지 리로드가 발생하여 `onError` 콜백이 상태를 설정하기 전에 컴포넌트가 언마운트됨
- **수정 내용**: `client.ts` 인터셉터에서 `accessToken` 보유 여부를 확인하여, 인증된 상태의 401(JWT 만료)일 때만 `/login`으로 리다이렉트하도록 수정
  ```ts
  // 수정 전
  if (error.response?.status === 401) {
    useAuthStore.getState().clearAuth();
    window.location.href = '/login';
  }

  // 수정 후
  if (error.response?.status === 401) {
    const wasAuthenticated = useAuthStore.getState().accessToken !== null;
    useAuthStore.getState().clearAuth();
    if (wasAuthenticated) {
      window.location.href = '/login';
    }
  }
  ```
- **재검증**: SCN-14, SCN-15 모두 PASS 확인

## 추가 관찰 사항

1. **SCN-22 오류 메시지 문구 차이**: 시나리오 문서에는 "해당 카테고리에 연결된 할일이 있어 삭제할 수 없습니다."이지만 실제 표시는 "할일이 연결된 카테고리는 삭제할 수 없습니다." — 의미는 동일하나 문구가 다름
2. **할일 날짜 UTC 표시**: 마감일이 UTC 그대로 (`2026-05-15T15:00:00.000Z`) 표시됨. 로컬 타임존으로 포맷팅하는 처리가 없음 — UX 개선 여지 있음
3. **필터 초기화 미동작**: 필터 "초기화" 버튼 클릭 시 라디오버튼이 "완료"로 선택된 채 유지됨 (SCN-08 이후 상태). "전체" 라디오로 복귀되는지 추가 확인 필요
