## 1. 제품 개요

**한 줄 소개**: 인증된 사용자가 카테고리별로 할일을 등록·관리하는 반응형 웹 애플리케이션

### 목적

개인 단위의 할일을 인증된 사용자별로 분리 저장하고, 카테고리·기간·완료 여부로 필터링하여 개인 생산성을 높인다.

### 목표 (v1.2.0)

- 회원가입/로그인 기반의 사용자 인증 제공
- 사용자별 독립된 할일 및 카테고리 관리 기능 제공
- 반응형 UI로 Web/Mobile Web 모두 지원
- 사용자 시력 보호를 위한 다크 모드(Dark Mode) 지원
- 글로벌 사용자를 위한 다국어(한국어, 영어) 지원 및 기기간 설정 동기화

## 2. 타겟 사용자

| 항목      | 내용                               |
| --------- | ---------------------------------- |
| 연령대    | 20대~50대                          |
| 직군      | 직장인                             |
| 접속 환경 | PC 웹 브라우저, 모바일 웹 브라우저 |

### 페르소나

| 항목      | 페르소나 A                                            | 페르소나 B                                       |
| --------- | ----------------------------------------------------- | ------------------------------------------------ |
| 이름      | 김민준                                                | 이수진                                           |
| 나이      | 32세                                                  | 47세                                             |
| 직군      | IT 스타트업 개발자                                    | 중견기업 팀장                                    |
| 접속 환경 | PC + 모바일 혼용                                      | 주로 모바일                                      |
| 목표      | 업무·개인 할일을 한 곳에서 카테고리별로 정리하고 싶다 | 팀 업무 중 본인 담당 할일을 빠르게 확인하고 싶다 |
| 불편함    | 메모앱에 흩어진 할일을 매번 찾기 번거롭다             | 마감일이 지난 할일을 놓치는 경우가 잦다          |

### 주요 사용 시나리오

1. 출근 후 오늘 해야 할 업무를 카테고리별로 등록한다.
2. 완료한 할일을 체크하고, 미완료 항목만 필터링하여 확인한다.
3. 모바일로 이동 중 마감일이 임박한 할일을 조회한다.

## 3. 기능 요구사항

### UC-01 회원가입

| 항목      | 내용                                                                        |
| --------- | --------------------------------------------------------------------------- |
| 액터      | 비인증 사용자                                                               |
| 사전 조건 | 가입되지 않은 이메일                                                        |
| 입력값    | 이메일, 비밀번호, 이름                                                      |
| 정상 흐름 | 입력값 유효성 검사 → 이메일 중복 확인 → 비밀번호 해시 저장 → 계정 생성 완료 |
| 예외 흐름 | 중복 이메일: 409 Conflict / 유효성 실패: 400 Bad Request                    |

### UC-02 로그인

| 항목      | 내용                                                                    |
| --------- | ----------------------------------------------------------------------- |
| 액터      | 비인증 사용자                                                           |
| 사전 조건 | 가입된 계정 존재                                                        |
| 정상 흐름 | 이메일/비밀번호 검증 → JWT Access Token 발급                            |
| 예외 흐름 | 이메일 없음 또는 비밀번호 불일치: 401 Unauthorized                      |
| 비고      | 향후 OAuth 소셜 로그인(Google, Facebook) 확장 고려하여 인증 레이어 설계 |

### UC-03 개인정보 수정

| 항목           | 내용                                          |
| -------------- | --------------------------------------------- |
| 액터           | 인증된 사용자                                 |
| 사전 조건      | 인증된 사용자 상태 (유효한 JWT 보유)          |
| 수정 가능 필드 | 이름, 비밀번호, 테마(light/dark), 언어(ko/en) |
| 수정 불가 필드 | 이메일 (BR-12)                                |
| 예외 흐름      | 미인증 요청: 401 Unauthorized                 |

### UC-04 할일 등록

| 항목      | 내용                                                                     |
| --------- | ------------------------------------------------------------------------ |

| 필수 입력 | 제목(title), 카테고리(categoryId)                                        |
| 선택 입력 | 설명(description), 종료 예정일(dueDate)                                  |
| 정상 흐름 | 입력값 검증 → 할일 생성 (isCompleted = false)                            |

### UC-05 할일 수정

| -------------- | ---------------------------------------------------------------------- |
| 액터           | 인증된 사용자                                                          |

| 예외 흐름      | 타인 할일 수정 시도: 403 Forbidden / 존재하지 않는 할일: 404 Not Found |

### UC-06 할일 삭제

| 항목      | 내용                                                |

| 예외 흐름 | 타인 할일: 403 Forbidden / 없는 할일: 404 Not Found |

### UC-07 할일 완료 처리

| 항목      | 내용                                                   |

## 4. 비기능 요구사항

| 항목           | 요구사항                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------- |
| 동시 접속      | 최대 300명                                                                                                    |
| 응답 시간      | API 응답 목표 500ms 이내 (일반 조회 기준)                                                                     |
| 보안           | 비밀번호 bcrypt 해시 저장, JWT 만료 시간 설정, HTTPS 적용, 비밀번호 최소 8자 이상 필수                        |
| JWT 저장 방식  | Zustand 메모리 저장 — localStorage·HTTP Only Cookie 미사용. 페이지 새로고침 시 토큰 소멸되어 재로그인 필요    |
| 설정 상태 저장 | 테마 및 언어 설정은 로그인 사용자의 경우 DB에 저장, 비로그인/초기 상태는 localStorage 또는 시스템 설정을 따름 |
| 데이터 보존    | 회원 탈퇴 시 사용자 및 관련 데이터(할일, 카테고리) 즉시 삭제 (CASCADE DELETE)                                 |
| 반응형 UI      | Breakpoint 기준: Mobile(~768px), Tablet(769px~1024px), Desktop(1025px~)                                       |
| 접근성         | 1차에서는 별도 WCAG 기준 적용 없음                                                                            |

## 9. 제약 사항 및 가정

| 구분 | 내용                                                           |
| ---- | -------------------------------------------------------------- |
| 제약 | DB 접근은 반드시 pg 라이브러리 직접 사용 (ORM 금지)            |
| 제약 | 1차 출시는 한국어 단일 언어, 라이트 모드 단일 테마             |
| 가정 | 소규모 개인 프로젝트 기준으로 별도 로드밸런서/캐시 레이어 없음 |
| 가정 | 기본 카테고리 목록은 서버 초기 데이터(seed)로 삽입             |
| 가정 | JWT 토큰 만료 정책 및 갱신 방식은 기술 설계 단계에서 확정      |
